# 题词／引文署名残留识别设计

## 目标

修复题词已经翻译、但拉丁字母作者姓名被质量检查误判为漏翻的问题，同时继续严格拦截未翻译或只翻译了一部分的题词正文。

## 已确认根因

真实 EPUB 的题词由一个 `blockquote` 组成：前一个直接子段落是引文正文，最后一个直接子段落是署名。模型把正文和书名翻成中文，只保留作者姓名 `Tom Stoppard`，并把英文标点 `—`、`,` 本地化为 `——`、`，`。现有姓名豁免要求源／译 inline 文本完全相同，因此未识别这个署名；后续 inline 残留检查把姓名当成英文作品名并报错。

## 方案

在现有 `_clearRetainedProperNames` 阶段新增“题词署名姓名”匹配，不直接放行整个 `blockquote`。候选必须同时满足：

- 位于 `blockquote` 最后一个有可见文本的直接子 `p`，且该段通过 `epi-att`、`epigraph-attribution`、`epigraph-author`、`quote-attribution`、`quote-author` 或 `attribution` 类显式声明为署名；
- 该段只有一个 `i`、`em` 或 `cite` 候选，候选是段落首个非空文本节点、没有任何子元素，且后面另有可见的作品信息；
- 源／译候选具有相同标签和 DOM 路径，二者均以一个或多个署名破折号开头；
- 源／译候选均以署名分隔符结尾；去除首尾署名标点后，作者姓名完全相同；
- 姓名是 2–6 个 Title Case 拉丁姓名词，不含中文、数字、URL 或说明性散文。

匹配后只清空质量检查副本中的署名 inline 节点，随后继续运行所有现有残留检查。因此作者名可以保留，但前面的英文引文、署名之外的英文散文或改变后的姓名仍会被拒绝。

## 错误边界

以下情况不豁免：非 `blockquote`、非最后署名段、没有署名破折号、多个 inline 候选、候选含书名或嵌套标签、源／译姓名增删或重排、整段英文引文未翻译。

## 验收

- 真实 `Tom Stoppard / Arcadia` 源／译 HTML 不再产生残留错误；
- 同一结构下题词正文仍为英文时继续产生 `longSourceText`；
- 姓名被修改或普通段落中的姓名不获得豁免；
- 质量检查与仓库安全测试全部通过；
- 用当前保存的真实 API 配置翻译题词章节通过；
- 整书从兼容缓存恢复后继续运行。
