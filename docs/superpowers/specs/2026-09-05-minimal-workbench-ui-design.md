# 极简工作台 UI 重设计

日期：2026-09-05

状态：用户已批准 B「极简工作台」；Flutter 界面已实现并通过规格复核。2026-09-24 完成回归测试与 Windows Release 编译。

## 1. 目标与边界

将 EPUB 翻译器的翻译、任务、预览、设置四个页面统一改为现代、克制、紧凑的工作台。不是仅替换主题色：同时调整导航、页面层次、控件密度、操作位置与状态反馈。

保持现有 Riverpod 状态管理、GoRouter 路由、翻译流程、缓存与持久化协议。此次不调整翻译算法、API 请求、密钥存储、任务状态机、章节筛选规则或导出逻辑。

用户在三套可交互原型中明确选择 B。A 的鼠尾草绿与宽侧栏、C 的暖纸色与横向导航不进入正式实现。

## 2. 视觉规范

### 2.1 配色与材质

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#FFFFFF` | `#151517` |
| 导航与次级区域 | `#F7F7F8` | `#1B1B1F` |
| 控件与局部容器 | `#F3F3F5` | `#232328` |
| 分隔线 | `#E7E7EB` | `#34343B` |
| 主文字 | `#27272D` | `#EEEEF0` |
| 辅助文字 | `#666670` | `#AAAAB4` |
| 主按钮背景 | `#303038` | `#E7E7EB` |
| 主按钮文字 | `#FFFFFF` | `#202024` |

以上为实现基准，不使用渐变、玻璃效果、大面积彩色背景或明显投影。成功、警告、错误保留小面积语义色，并且同时显示文字与图标，不能只靠颜色区分。警告使用琥珀色，错误使用红色。

普通文字与背景对比度目标不低于 4.5:1；焦点与关键控件边界应明显可辨。禁用状态不得与可点击状态混淆。

### 2.2 排版、间距与形状

- Windows 中文继续使用 Microsoft YaHei UI，英文继续使用 Segoe UI 及现有后备字体；不下载字体。
- 页面标题采用直接名称「翻译」「任务」「预览」「设置」，22–24 logical pixels，不使用原型中的宣传性大标题。
- 正文与表单值 13–14，辅助说明 12；不照搬 HTML 原型中用于视觉缩放的 9–10 px 小字。
- 区块标题 14–16，适度字重；预览正文行高 1.65–1.8，优先保证阅读舒适。
- 主间距使用 8、12、16、24、32；桌面页面内边距 28–32，窄窗口 16。
- 按钮与输入框圆角 6–8，主要内容容器不超过 10。列表优先使用分隔线，不做「卡片套卡片」。
- 常规表单与按钮高度约 40；图标按钮交互区域至少 40×40，触屏导航使用至少 48×48。
- 保留现有 0.9–1.3 倍文字缩放设置；不得用固定高度裁掉放大后的文字。

## 3. 应用框架与响应式

桌面使用约 72 logical pixels 宽的浅灰/深灰图标导航栏，顶部保留小型品牌标识，翻译、任务、预览依次排列，设置位于底部。品牌继续使用现有应用资源，本轮不更换 EXE 图标。

每个图标具有 Tooltip、可访问名称、键盘焦点及明确选中背景。当前页面标题始终可见，弥补纯图标导航的识别成本。不新增导航展开开关或持久化偏好。

窗口宽度至少 760 时使用图标栏；更窄时使用带文字的底部导航。页面内容最大宽度约 1200，宽屏保持合理版心。

根据导航之外的实际可用内容宽度决定布局：翻译内容达到 840 时为左右两列；预览内容达到 1040 时为章节目录加原译文双列，800–1039 时为目录加上下排列的原译文，小于 800 时目录与内容上下排列。

长路径、长书名允许换行或省略并提供完整信息提示；操作按钮可换行，禁止造成横向溢出。大字体下允许提前采用堆叠布局。

## 4. 四个页面

### 4.1 翻译

无任务时先呈现图书导入与偏好。有任务时当前状态、错误或输出操作位于图书与偏好之前，随后是工作流与辅助信息。此顺序来自 390×844、1.3 倍文字视觉验收：警告和可用输出操作必须留在首屏；输入与偏好仍在同一页紧随其后。

- 空状态：集中呈现 EPUB 导入区，支持现有文件选择、全窗口拖入与路径输入。目标语言、双语格式与输出位置保持可达。
- 已导入：左侧为文件名、路径、现有状态中可获得的章节统计和章节入口，右侧为目标语言及「仅译文 / 双语」选择。格式控件仍读写现有 `bilingual` 字段。
- 不增加封面解析或元数据提取。不把原型的 Walden 封面、作者、文件大小、固定输出路径或历史时间带入真实 UI；缺失数据采用文件图标或不展示。
- 操作栏位于图书与偏好区下方，显示真实输出路径及更改入口，根据现有能力显示「检查 / 重新检查」「开始翻译」或「取消」。一个状态只有一个视觉主操作；不得让多个相同的开始按钮争夺注意力。
- 风格分析开启时，未确认的风格内容默认展开，并显式说明需要确认才能翻译；确认后可以折叠成摘要。任务进行中保持现有编辑禁用规则，不能为了简洁隐藏阻止开始的原因。
- 进度区展示真实阶段、章节、进度、已有段落与预计信息。缓存扫描、恢复与正常翻译采用各自现有说明，无有效预计数据时不虚构剩余时间。
- 日志作为辅助区默认折叠，允许展开查看；可操作错误与警告不折叠进日志。保持日志内容、现有可用操作与文本可读性。
- 原型中的「最近任务」不复制到本页，正式任务记录集中在任务页面，避免重复显示与额外状态订阅。

### 4.2 任务

采用轻量行列表，以书名、摘要、状态、操作建立明确对齐关系，移除每行厚重背景和多重边框。

保留当前 `jobsProvider` 提供的任务顺序与数据，不新增排序、搜索、批量操作或伪造时间。长列表使用惰性构建，避免在页面总滚动容器内一次创建所有行。

根据现有能力显示打开输出、重试/继续入口；清空历史保留原有行为。运行中、完成、完成但有警告、失败、取消和可恢复状态分别具有明确文本。窄窗口把状态与操作放到行下方，不能挤掉任务名称。

### 4.3 预览

桌面左侧为章节目录，右侧为文本预览。目录保留推荐、仅正文、全部、全不选、重置及逐章勾选，保留手动覆盖标记。任务进行中禁止更改选择，但阅读不受影响。

目录在宽布局中独立滚动，章节多时惰性构建。选中章节发生变化或输入文件变化时沿用现有安全索引行为。

原文与译文在空间足够时并列，空间不足时上下排列。继续使用现有正文及译文摘录，不承诺完整 EPUB 渲染、段落精准对齐、译文编辑或搜索功能。尚无译文时显示明确提示，不能用原文假装译文。

章节路径、翻译段落统计及筛选规则保留为低视觉权重信息。无 EPUB 时显示真实空状态与返回翻译页的入口。

### 4.4 设置

统一为清晰的分组表单，顺序为「API 连接」「翻译偏好」「外观」，避免大面积独立卡片。页面保留纵向滚动，不增加一套新的设置路由或分类导航。

- API 连接：服务商预设、自定义地址、密钥、模型、连接测试及结果。密钥默认隐藏且可切换显示，继续使用已有安全存储与异步回填逻辑。
- 翻译偏好：稳定/均衡/快速预设、质量检查、风格分析。高级区域默认折叠，保留分块大小、并发、超时、重试次数、重试间隔、输出后缀、锁定术语表。
- 外观：中英文切换、跟随系统/浅色/深色、文字缩放。保留用户已保存的偏好与当前默认值，不在升级时强制切换为浅色。

设置继续自动保存，不添加没有实际意义的保存按钮。连接测试过程中有加载反馈，运行任务时沿用现有设置锁定策略；切换服务商不能覆盖另一服务商已保存的数据。

## 5. 状态与错误反馈

「完成但有警告」必须出现在翻译状态区与任务列表中，显示现有降级段落数量，说明部分内容保留原文。存在可用输出时仍允许使用当前平台的打开/分享/保存操作，不将其显示为普通成功，也不屏蔽可用译本。

原型中的「导出不完整译本」表示这项能力，不意味着要新增一套导出机制。正式实现采用与现有平台行为对应的文案，并在操作附近保留不完整提示。

可操作错误保留具体原因、修复操作和关闭入口，例如打开设置、降低并发、重试检查或翻译。长错误文本允许换行，不能遮挡恢复操作。

保持取消、缓存恢复、断点续译、历史重试与零翻译段落输出行为。本轮只重排展示，不改变按钮是否可用的业务判断。

## 6. 代码组织与数据流

| 单元 | 职责与边界 |
| --- | --- |
| `AppTheme` | 统一明暗色、排版与控件主题，避免页面散落同类样式 |
| `AppShell` | 响应式导航与已有窗口拖入桥接，不读取或复制任务业务 |
| `PageScaffold` | 页面标题、动作区与滚动框架；允许列表页提供惰性滚动主体，避免嵌套无限高度滚动 |
| `SectionCard` | 兼容现有调用的轻量区块，减少边框、圆角和装饰，不向业务层传递视觉状态 |
| 翻译展示组件 | 将输入、偏好、操作、进度、日志、风格确认分开组合，继续使用现有控制器回调 |
| 任务行与章节目录组件 | 负责响应式行布局、状态展示与交互，数据来自现有 provider |
| 设置分组与文本字段 | 复用已有字段同步和密钥隐藏状态，避免切换布局重置编辑内容 |
| `AppStrings` | 承载新增和调整的中英文文案，界面不新增硬编码语言混用 |

数据仍由 provider 流向页面与组件，用户操作通过现有 controller 回调写回。折叠展开等纯展示状态保留在 widget 局部，不新增任务或配置持久化字段。

仅为此次界面工作拆分过大的展示组件；不顺带重构翻译服务或修改无关分析警告。

## 7. 验证与交付

验收要求：

1. 四个页面采用 B 的统一视觉规范；没有旧版深蓝渐变侧栏、渐变标题区或卡片套卡片。
2. 明暗两种主题、中英文、现有文字缩放均可用。检查 1440×900、1024×768、800×600 和 390×844 布局；至少用 1.3 倍文字验证窄窗口关键操作，无溢出或按钮丢失。
3. 空状态、检查中、风格待确认、翻译中、恢复缓存、成功、完成但有警告、失败、取消均能找到对应下一步操作。浏览原型不作为正式软件的状态验证证据。
4. 运行现有 widget、排版、进度、设置及任务相关回归测试。对导航断点、警告可见性、折叠区可达性与响应式操作编写必要测试；不依靠只断言具体颜色数值的测试证明可用性。
5. 运行全量 Flutter 测试与静态分析，记录本次新引入的问题并消除，不顺带修复已有无关诊断。
6. 编译 Windows Release 并实际启动检查页面；交付完整 Release 目录中的 EXE 和依赖。未经新指示不自动合并或推送此次 UI 改动。

交付已进入 Flutter 正式实现，验证记录见 `docs/superpowers/plans/2026-09-05-minimal-workbench-ui.md`。浏览器原型仅作为已选视觉方向参考。

## 8. 自检结论

设计范围仅涉及展示层与必要的展示组件拆分。四个页面、主题、窄窗口及警告恢复能力均有明确要求；演示数据与实际软件能力已区分。没有引入新的服务依赖、模型迁移或未定义的产品功能。
