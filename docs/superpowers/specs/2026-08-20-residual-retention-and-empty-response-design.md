# 残留文本误判与空响应恢复设计

## 目标

修复中文目标翻译中的两类错误：

1. 将应保留的英文书名、作者名、出版社网址和短术语误判为未翻译正文；
2. 将一次性的空 API 响应直接升级为整次翻译失败。

修复必须继续拦截完整英文句子、部分未翻译的英文正文和结构损坏的响应。

## 已确认根因

`TranslationQuality.findSuspiciousHtmlResidual` 在 HTML 结构不完全对应、作品标题位于混合文本节点、或模型把标题放入 CJK 书名括号时，无法稳定识别 source-owned 文本。日志中的 `The Sovereign Individual`、`Strategic Investment`、`The Times`、作者姓名、网址和 `chum yum` 等合法保留内容因此触发 `FormatException`。当前翻译器会对残留质量错误重试，但重试不会改变判定规则，导致同一块连续失败。

`_translateSingleBlock` 在 API 返回空消息时抛出 `FormatException`。它已经经过通用重试循环，但达到尝试上限后只抛出没有 block 上下文的通用 `StateError`，用户无法判断是哪一块、是否属于 API 空响应。

## 设计方案

### 1. 保守的 source-owned 内容识别

在现有 HTML-aware residual pipeline 中增加一个只作用于“质量检查副本”的清理阶段，不修改最终译文。候选只有在源 HTML 与译 HTML 的标签、DOM 路径和文本内容对应时才可豁免：

- `<i>`、`<em>`、`<cite>` 中的匹配作品名；
- CJK 书名括号（`《》`、`「」` 等）包裹的匹配英文原题；
- 明确的作者签名或题词署名中的匹配姓名；
- URL、域名、出版社路径和短的全小写技术/音译术语；
- 书目、索引和尾注中的作者、期刊、出版信息。

清理后继续执行原有英文运行检测。以下内容仍必须报错：

- 完整英文段落或句子；
- 作品标题之外的长英文散文；
- 译文中被替换成另一个英文姓名/标题的内容；
- 结构不匹配、嵌套结构异常或没有源文本对应关系的英文片段。

### 2. 空响应专用恢复

将空消息作为独立的暂态 API 响应类别记录，同时沿用现有的可取消重试循环：

- 保持同一块内按现有最大尝试次数重试；
- 保持现有可取消退避，不改变正常网络错误和限流错误的策略；
- 每次重试提示模型返回完整 HTML 片段；
- 重试耗尽时抛出包含 block id、尝试次数和“API 返回空内容”的明确错误；
- 不把空字符串当作可用译文，也不静默降级为空 HTML。

### 3. 诊断与兼容性

保留现有 `_p13_failure_diag.log` 诊断格式，新增错误类型和最终处理结果的可读信息。缓存键、HTML 锁定逻辑和非 CJK 语言行为保持不变；不通过关闭 `residualQualityCheck` 来规避问题。

## 数据流

API 响应 → 提取消息 → 空响应检查/重试 → 锁定 HTML 结构 → source-owned 清理副本 → 残留检测 → 返回译文或记录单块降级。

空响应只在提取消息阶段重试；质量误判只在残留检测阶段处理，两个错误类别不混用。

## 测试验收

- 新增回归测试：CJK 书名括号中的 `The Sovereign Individual`、混合书名段落、作者/出版社 URL、`chum yum` 和 `agoric` 不再误报；
- 新增反例测试：完整英文句子、部分英文句子、改名后的英文姓名、结构不匹配的标题仍误报；
- 新增 API 空响应测试：空响应后第二次有效响应成功；连续空响应达到上限时抛出明确错误；
- 现有 `translation_quality_test.dart`、`repository_safety_test.dart` 全部通过；
- `flutter analyze lib test tool`、`flutter test` 和 Windows release 构建通过。
