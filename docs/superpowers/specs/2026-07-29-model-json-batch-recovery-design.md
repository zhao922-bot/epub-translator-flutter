# 模型 JSON 与合批失败恢复设计

## 背景

真实整书翻译在 458、490 和 660 块附近多次失败。已保存的错误证明存在两类响应问题：

1. 模型在 JSON 字符串中返回未转义的英文双引号，例如 `"所谓的"玻璃天花板""`，导致 `jsonDecode` 抛出 `FormatException`。
2. 跨文件脚注或受保护锚点合批响应漏掉、合并或重复块，导致响应块数量与请求数量不一致。

缓存恢复本身有效，但重新开始任务时旧错误仍残留在任务历史中，运行进度也没有持续同步到历史记录。

## 目标

- 兼容模型响应中可无歧义修复的未转义双引号。
- 保留现有块 ID、槽位 ID、数量和字段白名单校验，禁止错位译文进入缓存。
- 合批响应在多次尝试后仍不合法时自动拆小，避免单个异常响应中断整本书。
- 单块请求仍无法解析或验证时明确失败，不静默保留英文。
- 继续任务时立即清除旧错误，并让任务历史反映当前恢复和翻译进度。

## 不在范围内

- 不改变 EPUB 分块、样式档案、脚注锚点或缓存键算法。
- 不替换现有 OpenAI-compatible 请求协议。
- 不为任意损坏 JSON 做猜测性重建。
- 不吞掉 HTTP 认证、限流、网络中断或内容审核错误。
- 不记录 API 密钥或完整模型响应到磁盘。

## 方案选择

### 方案一：继续只重试

保持当前严格 JSON 解析并重复相同合批请求。实现最简单，但真实运行已经证明同一模型可能连续返回相同格式错误，无法解决问题。

### 方案二：改为非 JSON 标记协议

使用自定义分隔符返回槽位文本，从协议层规避引号转义。它会影响所有模型与现有测试，且翻译文本仍可能包含分隔符，兼容性风险最大。

### 方案三：严格解析、保守修复、验证、递归拆批

先执行标准 `jsonDecode`。仅在语法失败时，通过状态机修复 JSON 字符串内部、且后续字符不可能结束字符串的裸双引号，再次标准解析。解析成功后仍执行全部结构校验。结构不合法或仍无法解析时，对多块请求递归二分；单块仍失败则把原始异常交给任务层。

采用方案三。它不改变正常响应路径，修复范围可证明，并以现有严格验证作为安全边界。

## 组件设计

### 1. 保守 JSON 引号修复

在 `TranslationApiClient.decodeJsonObject` 内保持严格解析优先。第一次 `jsonDecode` 失败后，调用一个仅面向模型响应的内部修复器：

- 使用字符状态机跟踪是否位于 JSON 字符串以及前一个字符是否为转义符。
- 字符串内的双引号仅在下一个非空白字符为 `:`, `,`, `}`, `]` 或输入结束时视为合法闭合引号。
- 其他字符串内双引号前补反斜杠，例如 `"玻璃天花板"` 两侧的裸引号。
- 已正确转义的 `\"`、反斜杠和合法 JSON 不改变。
- 修复后仍交给标准 `jsonDecode`；如果依然失败，抛出原始解析异常，避免掩盖服务端真实问题。
- 解析结果仍必须是 JSON 对象。

该修复只处理字符串边界可判定的裸引号，不补括号、不猜字段、不增删块。

### 2. 受保护槽位合批递归拆分

把当前受保护槽位翻译分为两个职责：

- 单次合批方法：负责请求、重试、解析和完整结构校验。
- 恢复包装方法：捕获重试耗尽后的 `FormatException`，以及已有的 HTTP 413 回退条件。

恢复规则：

1. 如果请求数大于 1，按原顺序二分为左右两组并顺序执行。
2. 每组继续使用相同上下文、风格档案、术语表、取消令牌和请求计数回调。
3. 两组均成功后按请求 ID 合并结果。
4. 如果请求数为 1，保留异常并中止任务。
5. 网络、认证、限流和取消异常不因本功能拆批；继续沿用现有重试与错误处理。

普通正文中带受保护锚点的块和跨文件脚注共用该方法，因此都会获得同一安全回退。普通 HTML 批次不在此次改动范围内。

### 3. 任务历史同步

重新开始或从历史继续翻译时：

- 创建 `cacheRestoration` 任务时显式清除 `errorMessage`。
- 每次仓库进度回调同时更新当前任务和内存中的任务历史条目。
- 进度历史最多每秒持久化一次，减少缓存扫描期间的磁盘写入；完成、失败和取消状态仍立即持久化。
- 持久化历史使用已更新后的快照，避免保存状态更新前的旧列表。

独立断点文件仍是崩溃恢复的权威来源；任务历史用于用户可见状态，不替代块缓存和断点。

## 错误处理与安全性

- 自动修复成功不代表自动接受：响应仍必须通过块数、块 ID、槽位数、槽位 ID、字段白名单、HTML 锚点和翻译质量检查。
- 拆批只隔离故障范围，不降低校验标准。
- 单块失败会保留可续传断点，并向用户显示脱敏后的真实异常。
- 已完成的 660 块缓存不会被删除；下一次扫描仍可复用。
- 不把模型原始响应写入日志，避免书籍内容和潜在服务端信息泄露。

## 测试设计

### JSON 解析

- 合法 JSON 原样解析。
- `"所谓的"玻璃天花板""` 一类裸引号被修复并保留为译文内容。
- 已转义引号不被二次转义。
- 缺括号、非对象或结构性损坏仍失败。

### 合批恢复

- 多块受保护槽位第一次返回数量不匹配，拆为两组后成功，并保持原始结果顺序。
- 非法 JSON 的多块响应在重试耗尽后拆批成功。
- 单块仍返回非法 JSON 时抛错，不能生成或缓存伪结果。
- 取消和非 413 的网络错误不触发递归拆批。

### 任务历史

- 从失败任务继续时，当前任务和历史条目的旧错误立即清空。
- 缓存恢复与翻译进度回调同步更新历史中的块数、阶段和状态。
- 最终失败仍写入新的错误和最新断点进度。

## 验收标准

- 截图中的未转义 `"玻璃天花板"` 响应能被解析，并通过原有结构校验。
- 合批漏块不再直接终止多块任务；软件自动缩小批次并保存成功结果。
- 单块不合法时仍明确失败，不出现静默漏翻或错位。
- 点击继续后任务历史不再展示旧错误，且进度与当前任务一致。
- 定向测试、完整 `flutter test`、`flutter analyze lib test` 和 Windows Release 构建全部通过。
