# HTML 感知的源语言残留检测设计

## 背景与根因

《The Sovereign Individual》翻译到 `text/part0012_split_005.html` 的 `p-2` 时，模型返回了完整中文译文，并在源 EPUB 的斜体书名节点中保留了：

`The 500-Year Delta: What Happens After What Comes Next`

当前残留检测会先把 HTML 压平成纯文本。上述合法作品名因此变成 9 个连续英文词，被当成整段漏翻并触发重试。与此同时，单块重试结果中的 `entitlement概念`、`associated的` 等普通词漏翻没有达到“连续 7 个英文词”的阈值，反而被接受。

这造成质量倒置：较好的、符合风格档案要求的译文被拒绝，较差的中英混合译文可能进入缓存。

## 目标

- 允许模型在源 EPUB 明确标记的作品名节点中保留原始英文书名。
- 继续拒绝正文、引文或模型自行添加的长英文片段。
- 检出紧贴中文字符的普通小写英文漏翻词。
- 不改写译文，不删除英文，只负责接受或拒绝模型响应。
- 保留现有 HTML 结构锁、脚注锚点保护、重试和整块原子缓存语义。
- 不使现有 808 个缓存块失效。

## 非目标

- 不建立联网书名数据库或通行译名查询。
- 不实现通用命名实体识别。
- 不允许所有斜体英文自动通过；整段斜体引文仍必须翻译。
- 不重新扫描或重译已经写入缓存的历史块。
- 不改变翻译提示词、批次规划或缓存键。

## 方案对比

### 方案 A：HTML 感知的作品名豁免与混排检测（采用）

保留 HTML 结构信息，只豁免能与源节点一一对应、满足作品名特征的英文片段；对其余文本继续执行现有残留检测，并增加中英文紧贴检测。

优点是精度最高，符合风格档案；缺点是需要维护一组保守的作品名判定规则。

### 方案 B：所有长英文片段一律允许

实现简单，但会重新放过整句、整段漏翻，不满足质量要求。

### 方案 C：所有作品名强制翻译成中文

能避开此次误判，但会丢失无通行译名作品的原文信息，并与用户确认的风格档案冲突。

## 组件边界

### `TranslationQuality`

新增 HTML 感知的残留判断入口，输入：

- `sourceHtml`
- 经过结构锁定的 `translatedHtml`
- `targetLanguage`

它只返回质量判断，不修改任何 HTML。

现有纯文本 `hasSuspiciousSourceResidual` 保留，作为移除合法作品名后的基础检测器以及非 HTML 调用方的兼容入口。

### `EpubChapterTranslator`

`_validateTranslatedBlockQuality` 改为把源 HTML 和锁定后的译文 HTML 交给 `TranslationQuality`。异常、重试、批次降级和缓存写入流程保持不变。

## 作品名豁免规则

只有同时满足以下条件的英文片段才能从残留检测文本中排除：

1. 源节点和锁定后的译文节点在 DOM 结构中一一对应。
2. 节点标签是 `i`、`em` 或 `cite`。
3. 译文节点完整保留源节点的英文文本，而不是模型新造的英文。
4. 英文片段包含 3–16 个词，总长度不超过 140 个字符。
5. 忽略 `a/an/and/as/at/by/for/from/in/of/on/or/the/to/with/what/after` 等连接词后，多数实词符合标题式大小写。
6. 片段不表现为完整引文或普通句子：不以句号、问号、感叹号结尾，不包含多个完整句子。

判定不明确时不豁免，继续走原有残留检查。这样做是失败关闭策略，不会因为斜体标签而放过整段引文。

豁免只影响质量检查使用的临时文本，不会从最终 EPUB 删除书名。

## 普通英文漏翻检测

对去除合法作品名后的译文增加 CJK 紧贴检测：

- 目标语言为中文、日文或韩文时，查找长度至少 5 的全小写英文词。
- 如果该词与中日韩文字直接相邻，例如 `entitlement概念`、`associated的`，判定为可疑残留。
- URL、邮箱、合法作品名节点、全大写缩写、首字母大写专名和包含数字的产品名不应用此规则。

该规则刻意只检查“直接紧贴”，避免把正常保留且有空格分隔的术语、品牌和人名全部误判。

## 数据流

1. 模型返回 HTML 或槽位译文。
2. 现有结构锁使用源 DOM 重建译文，保留标签、属性和脚注锚点。
3. 新质量检查同时解析源 HTML 与锁定后的译文 HTML。
4. 收集严格匹配的合法作品名节点，并仅从质量检查副本中排除这些片段。
5. 对剩余文本执行现有长英文残留检测。
6. 对剩余 HTML 文本执行 CJK 紧贴小写英文词检测。
7. 任一检查失败则抛出 `FormatException`，沿用现有重试与降级流程。
8. 所有检查通过后，才允许上层以整块为单位写入缓存。

## 错误与日志

- 长英文正文仍使用现有“疑似源语言残留”错误。
- CJK 紧贴英文命中时，错误中记录脱敏后的词形预览和块 ID，便于区分“长段落漏翻”和“局部混排漏翻”。
- 不把完整模型响应写入日志，避免泄露书籍内容或服务端信息。
- 不改变断点：失败时已完成块继续保留，当前块不产生缓存。

## 缓存与续传

- 不修改缓存 schema、块缓存键或任务键。
- 当前 808/3034 缓存可以直接恢复。
- 失败的 `p-2` 尚未写入缓存；修复后只需重新请求该块。
- 历史上已缓存的结果不做追溯性重新校验，避免整书重译和额外 API 成本。

## 测试设计

### 应接受

- 本次真实 `p-2`：中文正文加源 `i` 节点中原样保留的英文书名。
- `em`、`cite` 中结构对应且标题式大小写的作品名。
- 中文正文中的 `PayPal`、`Microsoft`、`UN`、URL、邮箱。
- 合法方括号、数字和普通中文标点。

### 应拒绝

- 相同长英文书名出现在普通 `p` 文本中，而源节点不是作品名标签。
- 模型在译文中自行增加源文没有的英文标题。
- `i`/`em` 中的完整英文引文或普通句子。
- `entitlement概念`、`associated的` 等 CJK 紧贴小写英文词。
- 删除、移动或篡改脚注锚点的结果。
- 整段英文或一段中文一段英文的结果。

### 验证

- 新回归测试必须先在旧实现上失败，再在新实现上通过。
- 运行 `repository_safety_test.dart`、翻译质量测试和完整 `flutter test`。
- 运行 `flutter analyze lib test`。
- 用当前保存的 API 配置对真实 `p-2` 做一次验收，不在输出中暴露 API 密钥。
- 构建 `flutter build windows --release`，核验 `data/app.so` 哈希。

## 成功标准

- 真实批量译文因只保留合法书名而一次通过，不再被迫进入较差的单块翻译。
- 含 `entitlement概念`、`associated的` 的译文被拒绝并重试。
- 脚注、HTML 结构和现有缓存不受影响。
- 完整测试、静态分析和 Windows Release 构建通过。
